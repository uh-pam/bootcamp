Getting Python running

Start here · Python · P1 Reading: 4 pages With practice: ≈ 2 hours Assumes: nothing — start here

Why this lesson is here

You are going to spend more time reading error messages than writing code. That is not a sign of doing it badly; it is what programming is.

So this lesson is only half about installing Python. The other half is learning to read what the machine tells you when something goes wrong — because for the next few weeks you are working alone, and the traceback is the only thing that can tell you what happened.

Before you start

Nothing. This is the first lesson, and it assumes you have never written a line of code.

It does assume you have worked through Set up Python, which takes about an hour and leaves you with a bootcamp folder and JupyterLab.

Quick check. Can you start JupyterLab and see your data folder in its file panel?

TipShow the answer

Open a terminal and type, pressing Enter after each line:

cd bootcamp
.venv\Scripts\activate          # Windows PowerShell
source .venv/bin/activate       # macOS or Linux, instead of the line above
jupyter lab

A browser tab opens, and the panel on the left lists data. If any line fails, the setup page’s When something goes wrong section covers the usual causes.

The idea

Python is a language for giving a computer instructions. You write instructions in a plain text file: typed characters only, with none of the fonts or formatting of a Word document. A program called the interpreter reads that file and carries them out, one line at a time, top to bottom.

That is genuinely all that happens. There is no separate build step to think about and no magic. When something goes wrong, it went wrong on one specific line, and Python will tell you which.

There are two ways to run instructions, and you will use both:

  • A script is a file ending in .py. You run the whole thing at once. Use scripts when a task should run start-to-finish the same way every time.
  • A notebook is a file ending in .ipynb, made of cells you run one at a time, with output appearing underneath. Use notebooks to explore, and to mix explanation with code.

These notes are written as notebooks-in-spirit: every code block you see was actually run, and its output is printed underneath.

The mechanics

1. What setup gave you

Three things, each of which you will lean on in every lesson:

  • Python itself — the interpreter.
  • An environment, the .venv folder inside bootcamp. venv stands for virtual environment: a private copy of Python with this course’s packages in it. You must activate it each time you open a new terminal. Forgetting is the single commonest cause of “but I installed that already”.
  • JupyterLab, which runs in your browser and is where you write both scripts and notebooks.

Do not repeat the setup commands here. Typing mkdir bootcamp again from inside bootcamp makes a second bootcamp inside the first, and code that looks for data/cohort.csv stops finding it.

2. Your first program, as a script

In JupyterLab, choose File ▸ New ▸ Python File. An empty editor opens. Type one line:

print("Hello from my own machine")

Choose File ▸ Save Python File As…, name it hello.py, and save. It appears in the file panel, inside bootcamp.

To run it, choose File ▸ New ▸ Terminal. This terminal opens already inside bootcamp and uses the same Python as JupyterLab. Type:

python hello.py

and press Enter. The line of text appears underneath.

3. The same line, in a notebook

Choose File ▸ New ▸ Notebook (pick Python 3 (ipykernel) if asked). Type the same print(...) line into the empty cell and press Shift + Enter. The output appears directly under the cell, and a new empty cell opens below it.

That is the whole difference: a script runs top to bottom in one go; a notebook runs whichever cell you choose, when you choose. Every code block in these notes can be pasted into a notebook cell.

4. Read the traceback

Now make it fail on purpose. Change hello.py to this, save it, and run it again:

temperature = "22C"
print(temperature + 5)

Python stops and prints a traceback. It looks alarming and is not. It is a report with a fixed shape, and you read it from the bottom.

temperature = "22C"
print(temperature + 5)
---------------------------------------------------------------------------
TypeError                                 Traceback (most recent call last)
Cell In[1], line 2
      1 temperature = "22C"
----> 2 print(temperature + 5)

TypeError: can only concatenate str (not "int") to str

The bottom line is the answer: you tried to join a piece of text to a number, and Python will not guess what you meant. The lines above tell you it happened in hello.py, on line 2.

Worked example

A traceback, diagnosed and fixed.

Suppose you are asked to add up three measurements and one of them came from a text file, so it is still text.

This example uses = to give a value a name, a list (the square brackets), a loop and a conversion, which P2–P4 teach properly. You do not need to be able to write them yet. Text after a # is a comment: Python ignores it, and these notes use comments to explain a line. Read it for the method — how to go from a traceback to a fix — and come back to the syntax later.

measurements = [12.5, 13.1, "12.9"]
total = sum(measurements)
---------------------------------------------------------------------------
TypeError                                 Traceback (most recent call last)
Cell In[3], line 2
      1 measurements = [12.5, 13.1, "12.9"]
----> 2 total = sum(measurements)

TypeError: unsupported operand type(s) for +: 'float' and 'str'

Work through it in the fixed order.

Bottom line first. TypeError: unsupported operand type(s) for +: 'float' and 'str'. Something tried to add a number to a piece of text.

Which line? The traceback points at the sum(...) call.

What actually reached it? Look at the data:

measurements = [12.5, 13.1, "12.9"]
for value in measurements:          # run the indented lines once per value
    # repr(value) shows the value exactly; type(value).__name__ is its type's name
    print(repr(value), type(value).__name__)
12.5 float
13.1 float
'12.9' str

There it is. The third value is '12.9' with quotation marks — text that looks like a number. repr() shows the quotation marks that print() hides, which is why it is the right tool for this question.

The fix, stated deliberately rather than patched:

measurements = [12.5, 13.1, "12.9"]
numbers = [float(value) for value in measurements]   # a new list, each value made a float
print(sum(numbers))
38.5

Notice what we did not do: we did not delete the awkward value, and we did not wrap the whole thing in something that swallows the error. We found out what was actually in the data and converted it on purpose. That habit is worth more than any syntax in this lesson.

Try it yourself

Exercise 1 Predict the final line of the traceback, then run it.

print(x)
TipShow the solution

NameError: name 'x' is not defined.

Python has no idea what x is, because nothing has ever assigned a value to that name. This is different from a TypeError, which means the name does exist but holds something the operation cannot use.

Exercise 2 This one fails before it runs at all. Why is that different?

print("Hello
TipShow the solution

SyntaxError: unterminated string literal.

A string literal is text typed between quotation marks. The closing quotation mark is missing, so Python cannot even parse (read) the file into instructions. A SyntaxError is raised before anything executes, which is why you can get one from a line far below code that would otherwise have run.

The practical tell: if nothing at all printed, suspect a syntax error. If some output appeared and then it stopped, the program was running and hit a problem partway.

Exercise 3 You run a script and get ModuleNotFoundError: No module named 'pandas', but you installed pandas ten minutes ago. What is the most likely cause?

TipShow the solution

You are not in the environment you installed into. Check whether your prompt still shows (.venv); if not, activate it again. If this happened in JupyterLab, it was started from a terminal where the environment was not active: stop it with Control-C in that terminal, activate, and start it again.

The general shape of this error: Python is looking, and not finding, so either it was never installed or you are asking a different Python. Confirm which interpreter is running with the check in the next section.

Check it in Python

Every other lesson ends by checking a claim. This one checks your setup, which is the claim that matters here.

import sys
import numpy, pandas, matplotlib, scipy

print("python     ", sys.version.split()[0])
print("interpreter", sys.executable)
for package in (numpy, pandas, matplotlib, scipy):
    # f"..." puts values into text (P2); :<11 pads each name to 11 characters
    print(f"{package.__name__:<11}", package.__version__)
python      3.11.14
interpreter /home/hyperspace/anaconda3/bin/python
numpy       1.26.4
pandas      2.3.3
matplotlib  3.10.8
scipy       1.17.0

Two things to look at. The version should start with 3.12 or 3.11 — these notes were run on 3.11, which is why the output above says so. And the interpreter path — the chain of folders printed after interpreter — should point inside your .venv folder — if it points somewhere else, you are running the wrong Python, and that explains almost every “but I installed it” problem you will hit.

Keep this snippet. When you ask anyone for help, the answer is more useful if you paste its output with your question.

Common wrong turns

Where this usually goes wrong

Reading the traceback from the top
The top is the least useful part. The bottom line names the problem; work upwards only if you need to know how execution got there.
Assuming an error means you cannot program
Everyone who writes code sees errors constantly, including people who have done it for thirty years. An error is the program telling you something specific and true. It is information, not a verdict.
Installing the newest Python
The obvious download button gives a version newer than the pinned packages support, and pip install then fails, usually with a long build error that never mentions the Python version. Check python --version, install 3.12, delete .venv, and recreate it.
Forgetting to activate the environment
Then you are using a different Python with different packages. In a terminal you opened yourself, the prompt tells you: no (.venv) at the start means not active. Inside JupyterLab the prompt does not show it, so run the check in 1.6 and look at the interpreter path instead. This causes more confusion in week one than any other single thing.
Typing the prompt character
Examples sometimes show $ or > at the start of a line. That is the prompt, not part of the command. Type only what follows it.
Changing several things at once when stuck
Then you cannot tell which change helped. Make one change, run it, look at the result.
Pasting a fix you do not understand
It may work today and leave you unable to fix it tomorrow. Before you keep any snippet — from a forum, or from an assistant — make sure you can say what each line does.
