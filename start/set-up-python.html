Set up Python

You can read the mathematics without running anything. But every unit ends with a short piece of code that checks the idea, and typing those in yourself — and breaking them, and fixing them — is worth a great deal.

This takes about an hour, once. At the end you will have one folder on your computer that holds everything for this course, and a program called JupyterLab open in your web browser, where you will write and run all of your code.

If you would rather start reading now and set this up later, that is fine. Come back before P1.

1. Install Python

Install Python 3.12 — not the newest version. The large yellow button on python.org offers a newer Python, and the extra libraries this course installs in step 4 will refuse to install on it. Use one of these instead:

  • Windows: Python 3.12.10 for Windows
  • macOS: Python 3.12.10 for macOS. On a Mac with an Apple chip (M1 or later) you also need macOS 12 or newer — check under the Apple menu ▸ About This Mac — because one of the libraries has no version for older systems.
  • Linux: run python3 --version first; if it says 3.11 or 3.12, you have what you need.

Python 3.11 works equally well. Anything older or newer does not.

Open the file you downloaded and follow the installer. On Windows, tick “Add python.exe to PATH” on the first screen — it lets the terminal (step 2) find Python. It is easy to miss and awkward to fix afterwards.

2. Open a terminal

A terminal is a window where you type instructions instead of clicking.

  • Windows: press the Start button, type powershell, and open Windows PowerShell.
  • macOS: press ⌘ + Space, type terminal, and press Return.

A window opens with a line of text ending in a blinking cursor. That line is the prompt: it is waiting for you. Type a command, press Enter (Return on a Mac), and it runs. Nothing you type here will break your computer.

A terminal is always inside one folder, and it starts in your home folder — the one with your user name. Every command you run happens there unless you move.

3. Make your course folder

Type these one at a time, pressing Enter after each:

mkdir bootcamp
cd bootcamp

mkdir makes a folder called bootcamp inside your home folder. cd moves the terminal into it. You can see it in the ordinary way too: in File Explorer, open your user folder; in Finder, choose Go ▸ Home. It is empty for now.

Now make an environment — a private copy of Python for this course, so that nothing you install here can disturb anything else on your machine:

python -m venv .venv

On macOS and Linux, type python3 instead of python on this one line.

Then switch the environment on (“activate” it):

# Windows PowerShell
.venv\Scripts\activate

# macOS or Linux
source .venv/bin/activate

Your prompt now starts with (.venv). From here on, plain python works on every system.

If Windows answers “running scripts is disabled on this system”, type this, press Enter, answer Y, and then activate again:

Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

4. Install the packages

Python on its own does arithmetic and text. Packages are extra, free libraries that other people have written — for tables of data, for charts, for statistics. Install the five this course uses:

python -m pip install numpy==1.26.4 pandas==2.3.3 matplotlib==3.10.8 scipy==1.17.0 jupyterlab==4.5.3

This downloads quite a lot and takes a few minutes. The == numbers ask for exact versions, so that the numbers you get match the numbers printed in these notes.

5. Start JupyterLab

jupyter lab

Your web browser opens a new tab. That is JupyterLab. It is running on your own computer, not on the internet, and the panel on the left is your bootcamp folder.

Leave the terminal window open — closing it stops JupyterLab.

6. Get the data

Every example in these notes uses one small table.

  1. In JupyterLab, click the New Folder button above the file panel and name the folder data. Double-click it to go inside.
  2. Download cohort.csv and background_meta.csv. Your browser saves them to your Downloads folder.
  3. Back in JupyterLab, still inside data, click the Upload button (the upward arrow above the file panel) and choose both files from Downloads.

Above the file panel is the path: the chain of folder names leading to where you are. Click the folder icon at its start to return to bootcamp.

7. Check it all works

In JupyterLab’s Launcher tab, click Python 3 (ipykernel) under Notebook. A notebook opens with one empty box, called a cell. Click in it, paste this, and press Shift + Enter to run it. You do not need to understand it yet: it prints the versions you installed and the size of the data table.

import sys, numpy, pandas
print(sys.version.split()[0], numpy.__version__, pandas.__version__)
print(pandas.read_csv("data/cohort.csv").shape)

You should see:

3.12.10 1.26.4 2.3.3
(240, 7)

The first number may differ if you installed a different 3.12 or 3.11. If you see those two lines, you are set up, and everything else in this course happens in JupyterLab.

Every time you come back

JupyterLab needs starting again after you restart your computer or close the terminal. Open a terminal and type the same three lines each time:

# Windows PowerShell
cd bootcamp
.venv\Scripts\activate
jupyter lab

# macOS or Linux
cd bootcamp
source .venv/bin/activate
jupyter lab

Save your notebooks inside bootcamp, and code in these notes that reads data/cohort.csv will find the file.

When something goes wrong

It very often does, and the error message is usually more helpful than it looks.

Read the last line first. A Python error prints a long report called a traceback, but the final line names the problem.

ModuleNotFoundError: No module named 'pandas' means Python cannot see the packages from step 4 — almost always because the environment was not active. If you were in JupyterLab, stop it properly: closing the browser tab is not enough. Go to the terminal window it is running in, press Control-C (answer y if asked), or close that window. Then open a fresh terminal and type the three lines under Every time you come back.

FileNotFoundError for data/cohort.csv means your notebook is not in the bootcamp folder, or the files are not inside data. Look at the file panel: you should see data next to your notebook, and the two files inside it.

No such file or directory when activating means the terminal is not in bootcamp. Type cd bootcamp first.

Step 4 fails with a long error — often ending in metadata-generation-failed, Unknown compiler, or No matching distribution found — almost always means the wrong Python. Check with python --version. If it is not 3.11 or 3.12, install 3.12 from the links in step 1, delete the .venv folder inside bootcamp, and repeat from python -m venv .venv in step 3 — without the mkdir, since the folder already exists.

python: command not found on macOS or Linux means you need python3 for the one line that creates the environment. On Windows it usually means the PATH box was missed during installation; running the installer again and ticking it is faster than fixing it by hand.

Keep the whole error. If you need to ask someone, the exact text of the last line is the single most useful thing you can give them.

None of this is a test, and struggling with an install says nothing whatsoever about whether you can program. It is the least interesting part of the course and the only part where the computer, not the idea, is the obstacle.
